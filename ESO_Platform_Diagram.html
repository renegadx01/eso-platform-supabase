Claude API Integration

Where AI Is Doing the Work

Claude is integrated at two distinct points — once in the Micro bucket as the primary data-capture mechanism, and once in the Macro bucket as an analytical interface. Both use the Anthropic Python SDK with tool use. Neither pattern writes data outside its defined scope.

Anthropic SDK
claude-opus-4
Python SDK · Tool Use
🎙
EOW Interview Skill
Micro bucket — primary data input mechanism
  • Claude conducts the end-of-week check-in as a guided conversation — one per person per week
  • Extracts structured data: projects, planned hours, actions (ask/FYI), flags (info/critical), milestone slips
  • Writes a validated sidecar JSON + renders a formatted PDF/HTML report per person
  • Name reconciliation via alias map — unmatched names are flagged and skipped, never auto-created
  • Runs as a Claude Code plugin skill — invoked directly by team members
Conversation → Sidecar JSON → eow_db_write → Supabase
💬
Ask the Data
Macro bucket — natural language analytics interface
  • Chat page in the Streamlit dashboard — plain English questions over the full database
  • 9 read-only tool-use tools, one per table/view: people, projects, phases, allocations, actions, flags, milestones, time_entries, v_phase_burn
  • Each tool executes a Supabase .select() via the signed-in user's auth client — RLS enforced, never service_role
  • Claude reasons over returned rows and composes a structured answer
  • Current tradeoff: per-question fresh tool loop, no persistent tool history across turns
Natural language Q → Tool use → Supabase RLS → Answer

Open Decisions

  • Team model: one home team per person, or membership join table?
  • Which CRM feeds the pipeline table?
  • Billed vs logged: boolean flag or real invoice record?
  • Monograph actuals: periodic CSV importer now, or platform takes over hour tracking?

Known Gaps (Hard-Won)

  • View SQL bodies unverified — PostgREST cannot expose them
  • actions/flags have no dedup key — re-runs duplicate rows
  • time_entries empty — no structured actuals source yet
  • DB CHECK constraints hidden from introspection (found by trial)
  • Ask the Data has no persistent tool history across conversation turns

North Star Principle

  • Weekly adjustments (micro) must course-correct the long view (macro) in real time
  • Everything viewable and adjustable org-wide — by person, team, and project
  • Depth-first build, breadth-first schema: schema relationships are load-bearing walls
  • The EOW is the sensor. Supabase is the instrument panel.
